## 3. Ekrany

**Dashboard**: blok **„Aktywni klienci i projekty"** (ostatnio edytowane projekty, max 6: klient · projekt · status · ostatnia wycena) + „Nowy klient" + „Nowa wycena" (pyta o klienta/projekt, opcja „bez klienta"); pod spodem 4 kafle statystyk (w tym mies.: liczba wycen, wartość wysłanych, akceptacja %, średnia wartość); lista „Ostatnie wyceny" (5); karta „Subskrypcja" z paskiem postępu triala/okresu.

**Klienci (lista)** `/klienci`: szukajka (nazwa / e-mail / telefon / miasto — w Postgresie), pigułki *Aktywni / Zarchiwizowani*, sort; wiersz: nazwa, miasto, liczba projektów, wartość zaakceptowanych, ostatnia aktywność, menu `⋯` (Nowy projekt / Nowa wycena / Archiwizuj). Pusty stan z CTA „Dodaj pierwszego klienta".

**Klient** `/klienci/:id`: nagłówek (nazwa, kontakt, adres, status, „Edytuj"), zakładki **Projekty | Wyceny | Dokumenty | Pliki | Notatki**. Zakładka bez danych pokazuje pusty stan z akcją; zakładka, której funkcja jeszcze nie istnieje, **nie jest renderowana**.

**Projekt** `/klienci/:id/projekty/:pid`: nagłówek (nazwa, klient jako link, adres, metraż, typ, status jako select), zakładki **Wyceny | Dokumenty | Pliki | Notatki**. Wyceny grupowane po linii wersji: wiersz = najnowsza wersja (numer · v2 · status · suma), rozwinięcie = starsze wersje; przy zaakceptowanej — ptaszek i „Nowa wersja" ukryte pod `⋯`.

**Pliki** (zakładka klienta/projektu): strefa drag&drop na całą zakładkę + „Dodaj pliki"; lista: ikona typu, nazwa (inline-rename), rozmiar, data, kto; akcje: Pobierz / Podgląd (obrazy, PDF) / Usuń (potwierdzenie z nazwą). Pasek zużycia limitu w Ustawieniach → Pliki (ostrzeżenie od 90 %). Błędy: „za duży (max 25 MB)", „typ niedozwolony", „brak miejsca: zajęte X z 2 GB" — po polsku, **przed** wysyłką tam, gdzie się da.

**Dokumenty** (zakładka klienta/projektu): chronologicznie, wiersz = ikona typu dokumentu · numer wyceny · wersja · typ (Wycena / Termin / Etapy / Cennik / Pakiet) · data · „Otwórz". Bez ponownego renderu — to zapisany plik.

**Wyceny (rejestr)** `/wyceny`: tabela-karta: numer (+ badge `v2`), klient (link), projekt, tytuł, status (znacznik z T-08a; `archived` = wygaszony tor), suma, miasto, zaktualizowano, menu `⋯` (Nowa wersja / Duplikuj / PDF / Przenieś do projektu / Usuń). Filtry jako pills (statusy, w tym „archiwalne" domyślnie ukryte), filtr klienta. Pusty stan z CTA.

**Edytor wyceny** (najważniejszy ekran):
```
┌ Topbar: ← Wyceny | WYC/2026/08/0012 (edytowalne) | status pill | [Podgląd/Edycja] [PDF ▾] [⋯] ┐
├ lewa kolumna (flex-1) ───────────────────────┬ prawa kolumna (340px, sticky) ┤
│ Karta: Nagłówek (tytuł, klient, daty, wstęp)  │ Karta: Podsumowanie           │
│ Karta per Sekcja:                             │   Suma pozycji                │
│   tytuł sekcji (inline edit)                  │   Rabaty (terakota)           │
│   Grupa ▾ (inline edit, drag)                 │   ── Razem netto (duże)       │
│     ItemRow: [drag] [toggle] nazwa/opis  cena │   VAT / brutto                │
│     + Pozycja  + Z biblioteki                 │   Ważna do: …                 │
│   + Grupa                                     │ Karta: Klient (combobox,      │
│ + Sekcja                                      │   projekt, „Odśwież dane")    │
│                                               │ Karta: Dokumenty (3 ostatnie) │
└───────────────────────────────────────────────┴───────────────────────────────┘
```
Pasek edytora pokazuje ścieżkę: `← Kowalscy / Dom 164 m² | WYC/2026/08/0012 · v2`. Zakładki dokumentu: **Wycena | Termin | Dokumenty** (T-44/46). Pozycja „indywidualnie" w wierszu: „wycena indywidualna" w miejscu kwoty; `TotalsCard` dopisuje „+ N pozycji wycenianych indywidualnie". Jednostka przy ilości: „× 14 m²".
- `ItemRow`: toggle (czarny gdy on), nazwa bold, opis szary, cena tabular, w trybie edycji: input ceny, qty, handle, usuń, „zapisz do biblioteki" (ikona zakładki; po zapisie ptaszek).
- Podgląd = ten sam komponent bez kontrolek (jak `.edit-mode` w prototypie), **nie** osobny widok.
- Wskaźnik autosave przy numerze: „Zapisano 12:04" / „Zapisywanie…" / „Błąd — ponów".
- `LibraryPicker`: popover z wyszukiwarką, grupowanie po kategorii, Enter wstawia. Dla grup — osobna zakładka.

**Biblioteka** `/biblioteka` (od T-59; wcześniej: Pozycje / Grupy / Macierz): zakładki **Usługi | Grupy | Zestawy | Pomieszczenia | Stawki**.
- *Usługi*: pigułki grup („Wszystkie", „01 · Przygotowanie", …) + „Filtry" (aktywne/nieaktywne, sposób wyceny), licznik „38 usług", przełącznik lista–siatka (siatka = dotychczasowe karty), tabela: uchwyt kolejności · ikona · **Usługa** (nazwa + opis) · **Grupa** (pigułka w kolorze grupy) · **Sposób wyceny** (ikona + etykieta) · **Cena / stawki** („12,00 zł / m²", „od 250,00 zł", „indywidualnie") · **Aktywna** (switch) · `⋯`. „Pokaż więcej" po 50. Split-button **„Dodaj usługę ▾"** (Usługa / Zestaw / Import CSV). Szukajka w topbarze (⌘K) obejmuje usługi.
- *Grupy*: lista z drag kolejności, kod („01"), nazwa, kolor z palety (nie hex), licznik usług, badge „Przykładowa"; usunięcie przenosi usługi do „Bez grupy".
- *Zestawy*: dotychczasowe karty zestawów (T-10).
- *Pomieszczenia*: `RoomTypesSection` (ten sam komponent co w Ustawieniach).
- *Stawki*: macierz cennika (T-50).
- Dialog „Zastosować zmiany w otwartej wycenie?" przy edycji (kaskada) — tylko z panelu w edytorze (`LibrarySheet`).

**Edytor usługi** `/biblioteka/uslugi/:id` (T-61, układ z `inspiracja 2.jpeg`): nagłówek „← Biblioteka › Usługi", „Usuń usługę" (outline), **„Zapisz zmiany"** (CTA; zapis jawny, nie autozapis). Lewa kolumna — numerowane sekcje: **1. Nazwa · 2. Opis (licznik 73/500) · 3. Grupa (select, podpowiedź „Grupy pomagają uporządkować usługi w procesie projektowym") · 4. Sposób wyceny (8 kafelków z ikoną, jeden zaznaczony; pod spodem para `mode+unit`) · 5. Stawki według pomieszczeń (tylko `per_room`/`per_frame`: tabela pomieszczenie × stawka netto, drag, „Dodaj pomieszczenie", „Dodaj własne pomieszczenie") · 6. Ustawienia dodatkowe (cena „od", jednostka własna, „Aktywna w bibliotece", wariant-lider z T-52, etykieta `communication` z T-42)**. Prawa kolumna (sticky): **„Podgląd w ofercie"** (ten sam `ItemRow` w podglądzie; dla `per_room` lista stawek), **„Jak to działa?"** (tekst zależny od sposobu wyceny), **„Statystyki użycia"** („użyta w 24 wycenach, ostatnie 12 mies."), **„Wskazówka"** z linkiem „Zarządzaj pomieszczeniami" → zakładka Pomieszczenia.

**Szablony**: grid kart: nazwa, data, liczba pozycji, suma, ikony zawartości (wycena · termin · dokumenty); „Nowa wycena z szablonu", „Nadpisz bieżącą", usuń. Dialog zapisu z checkboxami zawartości (T-63).

**Ustawienia**: sekcje **Branding** (2 kolumny — formularz | live preview PDF) · Workspace · Biblioteka („Usuń pozostałe przykładowe (N)") · Pliki (pasek limitu) · Konto. Typy pomieszczeń **tylko** w Bibliotece → Pomieszczenia (T-73 — jedno miejsce do personalizacji).

**Pomoc** `/pomoc` (T-73): jedna długa strona — przyklejony spis treści po lewej (podświetla sekcję na ekranie), nagłówek z „Najczęściej szukane", 14 sekcji-kart z numerem „01…14", ikoną, leadem i blokami: kroki (numerowane jak na stronie usługi), lista, „Wskazówka" / „Uwaga" (05-UI §3a.5), tabela skrótów, FAQ. **Paleta ⌘K** (T-58): `command` z shadcn; grupy wyników: Klienci · Projekty · Wyceny · Usługi · Akcje („Nowy klient", „Nowa wycena", „Nowa usługa"). Enter otwiera, `⌘Enter` otwiera w edycji.

**Subskrypcja**: status, plan, data, przyciski; historia faktur — link do Portalu.

**Auth**: 1 karta na środku, bez sidebara. Login / Rejestracja (nazwa firmy + e-mail + hasło) / Reset / Google.

## 3a. Wzorce użyteczności z inspiracji (obowiązują wszystkie listy i formularze)

1. **Pigułki filtrów + licznik wyników** nad każdą listą (usługi, klienci, projekty, wyceny) — ten sam komponent (`FilterPills`), ta sama pozycja.
2. **Kolumna, która mówi „czym się różni ta pozycja"** (sposób wyceny, status projektu, wersja) — użytkownik nie ma otwierać rekordu, żeby to sprawdzić.
3. **Przełącznik stanu w wierszu** (Aktywna, status projektu) — bez wchodzenia w edycję.
4. **Pełna strona edycji z numerowanymi krokami i podglądem wyniku** dla rzeczy, w których łatwo o błąd (usługa ze stawkami; w przyszłości szablon). Szybkie poprawki (nazwa, cena) — inline na liście.
5. **„Jak to działa?" / „Wskazówka"** przy mechanizmach nieoczywistych: cennik wg pomieszczeń, rabat warunkowy, tryb godzinowy, wycena indywidualna, limit plików. Krótko, w miejscu użycia, z linkiem do właściwego ekranu — nie w osobnym „pomoc".
6. **Split-button „Dodaj ▾"** zamiast kilku przycisków; **„Pokaż więcej"** zamiast stron.
7. **Link do słownika z miejsca użycia** („Zarządzaj pomieszczeniami" z karty usługi), bez skoku do Ustawień.
8. **Zakładka, której funkcja nie istnieje, nie jest renderowana** (zasada z T-44) — żadnych „wkrótce".
9. **Puste stany rozróżniają „nie masz jeszcze" od „filtr nic nie zwrócił"** (zasada z T-07), zawsze z CTA.
10. **Błędy po polsku i przed akcją** tam, gdzie da się sprawdzić lokalnie (rozmiar pliku, typ, limit) — komunikat serwera to ostatnia linia obrony, nie pierwsza.

## 4. Komponenty shadcn do zainstalowania
`button card input textarea label select switch dialog sheet dropdown-menu popover command tooltip badge table tabs toast skeleton separator scroll-area avatar progress alert`

## 5. Interakcje
- Drag & drop: `@dnd-kit/core` + `sortable`, tylko w trybie edycji, sensory: pointer + keyboard.
- Inline edit: `contentEditable` **nie** — używamy kontrolowanych `<input>` stylizowanych na tekst (prostsze z React, bez problemów z kursorem). Enter = zapisz, Esc = cofnij.
- Kwoty: input przyjmuje „1 200", „1200,50", „1200.5" → `parseMoney()`; blur formatuje.
- Animacje: `framer-motion` tylko do `layout` przy reorder i wejść list. Bez przesady.
- Skróty: `⌘/Ctrl+S` wymusza zapis, `⌘/Ctrl+P` PDF, `⌘/Ctrl+K` paleta (f2).
